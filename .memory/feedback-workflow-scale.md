1. **起之前先确认**：任何事要起 Workflow，先跟主人说清楚打算怎么编排、为什么值得，等主人点头再起。不是不让起，是起之前要问（即使 ultracode 开着也一样）
2. **默认自己干**：读代码、做设计、写实现，自己小步快跑就行，不是所有活都要 Workflow
3. **小改动不审**：几十行、单一逻辑单元的 bug 修复，测试和门禁过了、真机验过就直接收工，不起审查（主人 11-16 修 #12 时：「这个小 bug 就没有必要审了，不要大炮打蚊子」）。连「要不要审」都别问，大改动才起
4. **审查只审一轮**：改完起一轮审查，把核实过的问题修掉就收工，不再起第二轮复审（主人 11-15：「审一轮已经很够意思了，修了就没问题，第二轮不用审」）。AGENTS.md「审到再无新发现」在这里让位于主人的这条
5. **真要起时控制规模**：一次 5 个左右，链路两段以内：并行分析 → 一个核实者统一逐条核实。不要每条 finding 派 N 个反驳者，也不要每个维度各配一个核实者，也不要多轮 loop-until-dry 的长链
6. **审查维度要全**：除了正确性，必须同时审**架构**（分层、依赖方向、职责边界、好不好扩展）、**工程审美**（干净不拧巴、状态机清晰、命名与规模、过度防御/过度设计）、**去冗余**（死代码、重复逻辑、可删的分支和参数、注释文档与代码不符）。不要在提示里写「不报风格偏好」把审美类发现挡掉（主人 11-14：「你只是审查正不正确……还要去审工程审美、去冗余的问题，以及架构的问题」）

**Why:** 2026-11-13 主人：「一定要注意控制 agent 的数量，可千万不要把额度给打爆炸了」「链路太长了就会很慢，而且很消耗额度」。2026-11-14 做自动更新功能前我正要起 Workflow 调研，被主人打断：「不要滥用 workflow，咱们用小步快跑的策略去做，你一个人的能力也是很强的」「以后起 workflow 去做任何事之前，你得先跟我确认」。

**How to apply:** 想起 Workflow 时先停下，用一两句话问主人（打算几个 agent、各干什么）；没得到确认就自己读、自己做。与 [[skill-routing-general]] 里的编排 skill 配合使用。
